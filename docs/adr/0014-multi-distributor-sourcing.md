# Adopt a flag-gated Multi-Distributor Sourcing engine with immutable evidence generations

> **Path update (ADR-0030):** references to "PI-6" below now resolve to `src/onboarding/image-verification/` (the relocated rights-and-identity verification pipeline). The verification contract itself is unchanged.

The Sourcing stage exists in the item-centric onboarding pipeline (Sourcing → Discovery → Extraction → Curation → Review → Promotion) but its distributor-evidence engine was never shipped: the evidence-attempt writer was removed in a dead-code sweep (`7e11c47`), no production code ever wrote `onboarding_evidence_attempts`, and the capability was gated default-OFF by the Sourcing safety patch (`BAYSTATE_CMS_SOURCING_ENABLED`). This ADR ratifies the authority, provider, generation, routing, and rollout contracts for rebuilding Sourcing as a real engine — reusing the recovered multi-distributor "V2" work (preserved in `stash@{1}`/`dc01ea6`) adapted to the current six-stage, capability-gated architecture.

**Status**: implemented (ADR ratified as the prerequisite; implementation completed per `docs/plans/sourcing-v2-recovery-plan.md` — schema/repositories (M2), provider-neutral engine + Phillips/BCI connectors (M3), reconciler + flag-gated worker leg (M4), conflict API + Settings surface (M5), capability-gated drawer (M6), end-to-end acceptance suite (M7). The capability remains DEFAULT OFF; the staged enablement sequence is documented in `docs/runbooks/sourcing-engine-rollout.md`.)

**Context**: distributor data was always meant to be supporting identity evidence that enhances Discovery, never canonical merchandising content. The recovered V2 work added the persistence model (connections, catalog snapshots, conflicts, acceptances, evidence attempts with connection/snapshot/version/observed/expiry fields), a `processSourcing` worker leg, and a reconciliation layer, but it predates the current architecture: it still routed coherent bundles to Curation (`bundle_to_curation`), used a three-argument stage-transition helper, and had no provider engine (the connector implementations lived only in the separate BayState repository). The Sourcing safety patch (ADR 0007 amendment) established the non-negotiables this ADR now formalizes: no Branding stage; Sourcing advances only to adjacent Discovery; direct Sourcing → Curation routing is prohibited until a separate structured-record fallback ADR exists; hard identity conflicts stay in Sourcing review until resolved. Ratifying this ADR is the prerequisite for implementing the engine; the capability must remain default-OFF until implementation, shadow observation, and measured manual/automatic rollout gates are satisfied.

**Decision drivers**:

- Distributor evidence is third-party identity evidence that should inform the operator and the Discovery stage — it must never fake an official source URL, never bypass Discovery's verified-source requirement, and never become canonical merchandising truth.
- UPC/GTIN is the strongest product identity signal and must be the primary lookup key; brand is advisory. A missing or stale brand profile must never imply `not_stocked`.
- Evidence must be immutable and generation-scoped so retry supersedes rather than mixes evidence; operators must always be able to see why a decision was made.
- Credentials never live in configuration, logs, errors, or API responses; connections store only a `secret_ref` resolved server-side at execution time.
- The worker may automate only deterministic, verifiable transitions; hard conflicts and anything requiring judgment remain manual, and model self-reported confidence is never an acceptance metric.
- Rollout must be reversible with the outer env flag as a kill switch; a phased shadow → manual → automatic sequence over measured outcomes is required before any environment turns the capability ON.

**Decisions**:

- **Sourcing is a flag-gated engine capability, not a new stage.** The six-stage pipeline is unchanged and no Branding stage is added. `BAYSTATE_CMS_SOURCING_ENABLED` defaults OFF and fails closed on missing/malformed values. While OFF, imports enter Discovery directly, reset/retry on a Sourcing item performs the audited `fallback_to_discovery` operator-override, and the Sourcing stage panel is read-only with a "Continue to Official Site Discovery" action — exactly the safety-patch behavior, preserved byte-for-byte. The engine applies to new imports; the 148 stranded legacy `sourcing/pending` rows are never automatically repaired or backfilled and continue through the operator Continue-to-Discovery action.
- **Distributor evidence is supporting identity/Discovery evidence, never canonical merchandising authority.** Sourcing may propose/confirm a brand hint and identity fields (name, brand, identifiers, weight, variant attributes), but it never establishes final catalog Brand truth and never asserts commerce authority. The recovered `DistributorAuthorityPolicySchema` (skuAuthority/pricingAuthority/inventoryAuthority/copyContributionMode) is narrowed for this CMS: v1 Sourcing uses identity fields only; commerce price/inventory authority is NOT granted by this ADR and is deferred.
- **Lookup is UPC/GTIN-first with exact normalized identifier matching.** Each enabled connector is invoked with a normalized 8–14-digit UPC/GTIN; a brand-only lookup is not expressible. Brand is advisory: an optional workspace brand-profile registry may order provider preference, but a missing/stale profile falls open to every enabled connection and never produces `not_stocked`. An HTTP 200 with the wrong size/pack/variant is a hard conflict or a not-found — never a `found` coherent result. `found` requires an exact normalized identifier match AND a variant-consistent record.
- **Provider-neutral engine contract.** `src/onboarding/sourcing/` defines `SourcingLookupRequest`, `DistributorCatalogRecord`, and a `DistributorConnector.lookupByGtin(request)` returning exactly one of `found | not_stocked | source_error`; no throw crosses the engine boundary. Connector types are closed to `api | ftp_catalog | csv | legacy_adapter`. Phase 1 production adapters are Phillips (REST, referenced `x-api-key`) and BCI/OrderCloud (REST, OAuth2 client-credentials token, memory-only/redacted). Phase 2 is Orgill and PFX via SFTP (fixed-width/CSV catalog snapshots) — separately reviewed for the `ssh2-sftp-client` dependency, host-key verification, size/time bounds, and quarantine. Central Pet EDI 832 is excluded (reference is a stub). Unknown connector types, missing/redacted secrets, malformed config/response, timeout, cancellation, and transport failure are durable `source_error` outcomes with stable non-secret codes.
- **Connector registration and auth use `secret_ref` only.** Connection rows store `secretRef` (an env var name or `api_keys` service name) plus non-secret configuration; raw passwords, tokens, API keys, and private keys are forbidden in `configuration_json`, source, logs, errors, and API responses (schema-level recursive/case-insensitive rejection of credential-shaped keys and values). Secret resolution occurs server-side immediately before connector execution and never returns resolved material to callers. The API reports a boolean `secretConfigured`, never `secret_ref` contents or resolved credentials.
- **Evidence attempts are immutable and generation-scoped.** The migration carries `sourcing_generation_id` (plus `distributor_connection_id`, `catalog_snapshot_id`, `catalog_version`, `observed_at`, `expires_at`) on `onboarding_evidence_attempts`. A generation is a durable run identity: one row per item with status, timestamps, and supersession identity — NOT `retry_count` reuse. Retry/reset supersedes the old generation and schedules a clean generation; stale generations remain audit-visible but can never influence reconciliation, acceptance, conflict completion, or routing. The evidence writer appends exactly once (deterministic idempotency key or unique generation+connection attempt key) and never updates prior attempts.
- **Single evidence writer and normalized acceptance/conflict authority.** `insertEvidenceAttempt` is the only writer and validates connection/workspace/item/generation ownership. `recordAcceptances` validates every attempt before insertion with `ON CONFLICT DO NOTHING`. Conflicts persist durably (`onboarding_evidence_conflicts` + candidates, idempotent per generation/field/value so worker retry cannot duplicate open conflicts). Exact identifier/pack/variant disagreement and contradictory returned brand evidence are `hard` conflicts; soft copy disagreements retain provenance and do not block Discovery. Acceptance/conflict readers select only the current generation.
- **Routing is adjacent-only and Curation is unreachable.** Sourcing may route only to Discovery. New route `evidence_to_discovery` accepts coherent current-generation evidence and moves the item to `discovery/pending`; no evidence or all-`not_stocked` uses `fallback_to_discovery`; hard conflicts produce `needs_input_conflict` and the item stays `sourcing/needs_input` until resolved. `bundle_to_curation` remains parseable in `SourcingRouteEnum` only as a legacy audit value — no schema, request, repository transition, worker, route, or UI may create or act on it, and `use_selected_bundle` is not re-added. A dedicated `completeSourcingWithDecision(itemId, decision, targetStage: 'discovery' | 'sourcing')` CAS-guarded helper performs the only automatic Sourcing completion; it rejects `curation`, non-Sourcing rows, route/target mismatches, and unresolved hard-conflict advancement. Generic advancement endpoints never advance `needs_input` or unresolved-conflict items.
- **Manual advancement vs automatic completion.** The worker's `processSourcing` (when enabled) may complete coherent or no-evidence items to Discovery (automatic mode) — it always lands the item in Discovery, never skipping a stage. Conflict resolution (`resolve_candidate | custom_value | dismiss`) is always manual: resolving one of multiple hard conflicts leaves `sourcing/needs_input`; resolving the last hard conflict atomically completes with `evidence_to_discovery` and moves to `discovery/pending` in one transaction. `dismiss` is explicit audit and clears a hard conflict only under the ADR's operator-override policy, never silently.
- **Evidence enhances Discovery, never replaces it.** Discovery still finds and verifies the official product page before Extraction; no fake source URL is created. A real distributor product-page URL is retained as evidence and surfaced to the operator; identity/name/brand evidence from current-generation attempts is available to Discovery as a narrowly typed projection. Distributor images are display-only in v1 — URLs may be shown read-only with provider/source/generation labels and a "not approved for catalog use" marker, and they may not be copied to `extraction_data_json`, classification evidence, drafts, or promotion until a PI-6 rights-and-identity verification pass is separately approved.
- **Retention, expiry, and cache semantics.** Each attempt records `observed_at` and `expires_at` plus `catalog_version`/snapshot identity. Cache reuse requires the same connection, the exact normalized identifier, an unexpired catalog snapshot/attempt, and a compatible catalog version — and still creates or explicitly links a current-generation attempt. A stale generation can never be accepted directly. Evidence rows are audit records: they are never deleted automatically — `expires_at` governs cache REUSE only, not row deletion; removal happens only through an explicit, separately reviewed operator action.
- **Rollout modes with the outer flag as kill gate.** `shadow`: run sampled lookups and persist/inspect observations without changing item stage/decision/acceptance (no item mutations). `manual`: new imports enter Sourcing; the operator completes or retries every item; hard conflicts always manual. `automatic`: the worker may complete coherent/no-evidence items to Discovery; hard conflicts remain manual. The ADR defines measured thresholds (retrieval, exact-product/variant correctness, conflict/error rates, latency, secret/redaction violations) that must be met for each mode transition; model self-reported confidence is never an activation metric. `BAYSTATE_CMS_SOURCING_ENABLED=false` + restart returns new imports to Discovery immediately and makes Sourcing retries use the audited fallback; historical evidence remains readable.
- **Advisory brand-profile registry is workspace settings only.** The optional brand → ordered-distributor-IDs profile lives in Settings (never a pipeline stage), stores no credentials, is advisory and fall-open, and never constitutes a Brand authority. There is exactly one brand authority surface in the pipeline — none is created here.

**Consequences**:

- Implementing the engine requires this ADR ratified first: Milestone 2 recovers/adapts the V2 migration and repositories (gated `distributor_v2_schema_version` block after the existing 13-column evidence-table creation, PRAGMA-guarded ALTERs for the five recovered columns plus `sourcing_generation_id`, `IF NOT EXISTS` for the six other recovered tables, `foreign_key_check`, marker written only after success), Milestone 3 builds the provider-neutral engine and Phase 1 REST connectors (injected transport, no real network in tests), Milestone 4 integrates the flag-gated worker and reconciler, Milestone 5 exposes capability-gated routes and a Distributors settings tab, and Milestones 6–7 merge the single capability-gated Sourcing drawer and recover/adapt the six V2 test suites plus the five safety-patch suites.
- The capability stays default-OFF after delivery. Any environment may enable it only through the rollout sequence (flag OFF → shadow → manual dev ON → automatic dev ON → real imports), with the documented kill action (`BAYSTATE_CMS_SOURCING_ENABLED=false` + restart). Dev connector configuration adds secret references and disabled connections first; no provider is contacted during CI or migration.
- No live provider call, paid crawl, model call, or live DB write happens during implementation or tests; network work is bounded, cancellable, and outside import/database transactions.
- No catalog/ShopSite write, Git catalog activation, staging, or commit is part of this work; the dirty worktree (safety patch + unrelated concurrent work) is preserved, with no stash/reset/clean.
- Deferred items: structured-record fallback Extraction (own future ADR), Phase 2 SFTP dependency approval, PI-6 image rights/identity integration, commerce price/inventory authority, and removal of the non-cohort distributor image backfill in `product-curator.ts` (fail-closed image exclusion is the required security correction).
- Legacy `bundle_to_curation` persisted decisions remain readable audit records and are never acted on; tightening legacy-route semantics for `evaluateItemReadiness` (which currently treats any non-null sourcing decision as source-finalized) may require a separate compatibility migration.

# Amendment A — Default-On Distributor Sourcing and Distributor-Record Extraction

**Status**: ratified (product-owner directive of 2026-08-14; implementation follows `docs/plans/default-on-sourcing.md`).

**Product-owner directive (quoted)**: *“Default on. We always want to check our distributors first, and skip discovery if we find the product on our distributors.”*

This amendment supersedes the following clauses of the base ADR:

- **Default-OFF** → the engine capability is now **default-ON**. An absent `BAYSTATE_CMS_SOURCING_ENABLED` means **enabled**; an explicit `false|0|no`, an empty/whitespace value, a malformed value, or an invalid `BAYSTATE_CMS_SOURCING_MODE` value disables the capability **fail-closed**. Explicit `false` remains the global kill switch.
- **Adjacent-only Discovery routing** → Sourcing now has **two** automatic completion targets: Discovery (unchanged routes `evidence_to_discovery` / `fallback_to_discovery` / `degraded_fallback_to_discovery`) and **Extraction via the new route `distributor_record_to_extraction`**, the *only* automatic Discovery-skipping route.
- **“Evidence enhances Discovery, never replaces it”** → when a **qualified** distributor record is established, Discovery is **skipped** and the item routes directly to `extraction/pending` with item/extraction `source_type='distributor_record'`. Discovery still runs automatically when a qualified record cannot be established (no identifier, all `not_stocked`, insufficient record, provider failure, or operator fallback), and operators may always request official-site Discovery later.

All other base-ADR clauses — including the `bundle_to_curation` prohibition, evidence immutability and generation scoping, `secret_ref`-only credential handling, UPC/GTIN-first exact matching with brand advisory, hard-conflict manual resolution, review-mandatory, and image display-only rules — remain in force and are reaffirmed below where they interact with the new routing.

**Normative amendments**:

1. **Default-on; kill switch retained.** `BAYSTATE_CMS_SOURCING_ENABLED` absent = enabled; explicit `false|0|no` (trimmed, case-insensitive) = disabled (kill switch); empty/whitespace/malformed enabled value = disabled fail-closed. `BAYSTATE_CMS_SOURCING_MODE` absent = `automatic`; `observe|manual|automatic` = that mode; empty/whitespace/invalid mode = **effective disabled** fail-closed. Flags expose a stable non-secret `reason` code (`default_on | env_enabled | env_disabled | malformed_config | invalid_mode | override`). Existing installations must pin `BAYSTATE_CMS_SOURCING_ENABLED=false` during upgrade until the rollout gates pass.
2. **Durable entry-policy version.** A `sourcing_entry_policy_version` column (integer, default 0) marks import eligibility. The 148 stranded legacy `sourcing/pending` rows are policy `0` and remain operator-controlled via **Continue to Official Site Discovery** — they are never automatically claimed, looked up, or backfilled. Only post-amendment import call sites (spreadsheet import and reviewed Agent Lab create-import) write policy `1`. Sourcing claim/observe queries require exactly the current version. No timestamp/stage heuristic may set `1`.
3. **Qualification floor.** “Found” for the Discovery skip requires: exact normalized UPC/GTIN equality; current-generation, schema-valid, **accepted** evidence; at least one nonblank distributor product name; no unresolved hard identity conflict; and a complete, deterministic v1 projection. Model/self-reported confidence never grants acceptance. One qualified provider is sufficient (many products are single-distributor); all enabled providers are still queried within the bounded generation. When multiple providers return records, every shared identity-critical value must agree or the item blocks (`needs_input_conflict`).
4. **Route/target matrix.** `distributor_record_to_extraction` → `extraction/pending` (source_type `distributor_record`). `evidence_to_discovery` → `discovery/pending` (accepted but insufficient evidence, or explicit official-site path). `fallback_to_discovery` → `discovery/pending` (kill switch OFF, legacy item continue, no identifier/connection, all `not_stocked`). `degraded_fallback_to_discovery` → `discovery/pending` (provider errors with no qualified record). `needs_input_conflict` → stays `sourcing/needs_input`. A qualified record plus another provider’s `not_stocked`/`source_error` still routes to distributor Extraction with warnings retained. `bundle_to_curation` remains parse-only legacy audit — no writer, request, transition, worker, route, or UI may create or act on it; direct Sourcing → Curation remains prohibited.
5. **Route-specific schema invariants.** `distributor_record_to_extraction` requires nonempty sorted-unique accepted evidence attempt IDs, provider provenance, `sourcing_generation_id`, source type, and a deterministic `evidence_hash`. Decisions are validated at every repository/API boundary; a read-only legacy parser preserves historical rows.
6. **Source types and null URL.** Items and extractions carry `source_type` `official_page | distributor_record`. `onboarding_items.source_url`, `ExtractionData.sourceUrl`, and `onboarding_extractions.source_url` remain **null** for distributor records — no fake URL is ever invented. A real distributor product-page URL stays on its immutable `EvidenceAttempt.evidenceUrl`, displayed as evidence only.
7. **Source-dispatched Extraction.** Extraction branches on persisted source type. `official_page` keeps the current URL/profile/page-scrape path. `distributor_record` uses deterministic structured-record materialization: `extraction_method='distributor_record_v1'`, nullable `source_url`, source type, accepted attempt IDs, generation ID, and evidence hash — with **no URL fetch, no extractor profile, no DOM parse, no OCR, and no model call**. Materialization revalidates current-generation ownership and open-conflict state; integrity failure leaves Extraction failed and offers audited fallback to Discovery (never fabricated data).
8. **v1 identity-field allowlist.** Distributor-record materialization may carry only: exact UPC/GTIN; distributor SKU; manufacturer part number; product name; noncanonical brand evidence; weight; and whitelisted variant attributes (`size`, `count`, `packCount`, `flavor`, `formula`), plus provider/attempt/generation/catalog-version/observation provenance. **Excluded**: description/bullets/marketing claims, price, inventory, images, and arbitrary provider fields.
9. **Variant identity authority.** `flavor`, `formula`, and every connector-declared variant axis are **hard** identity fields. An unclassified/unknown variant-bearing attribute makes the record **insufficient** for the Discovery skip (never silently ignored, never soft).
10. **Classification evidence source.** Distributor classification evidence receives its own `distributor_record` source label; it must **never** be labeled `official_product_page`, and it is never claim/composition authority unless a future canonical configuration explicitly permits it.
11. **Frozen cohort evidence.** Frozen cohort/curation evidence versions its projection and retains source type plus distributor provenance (sorted accepted attempt IDs, generation, evidence hash). Distributor-provenance is preserved through cohort Curation; live values are never read after freezing.
12. **Images (PI-6).** PI-6 remains the sole path for distributor images to become commerce-approved. Raw distributor image URLs stay display-only in evidence; they are never copied into `extraction_data_json`, classification evidence, drafts, or promotion until PI-6 verification passes. The promotion image path may only consume accepted, current-generation, workspace-owned evidence (the prior UPC-wide/raw-attempt ingestion is a security defect and is fixed fail-closed).
13. **Provider errors, conflicts, and resolution.** Hard conflicts (including flavor/formula/axis disagreements) remain `sourcing/needs_input` until operator resolution. Provider errors with no qualified record → `degraded_fallback_to_discovery`. After operator resolution: a still-qualified resolved bundle routes to `distributor_record_to_extraction`; otherwise to Discovery. `dismiss` omits the disputed field; it does not silently choose a provider. Retries supersede generations exactly as in the base ADR.
14. **Rollout modes and gates.** `observe` evaluates/persists observations without item-stage/acceptance mutations; `manual` requires operator completion of every item (hard conflicts always manual); `automatic` lets the worker complete coherent/no-evidence items. Before automatic production activation, **each connector** must pass: all offline fixture/security tests; ≥100 labeled observations (≥30 known-found, ≥20 negative/wrong-variant); **zero** false `found`, wrong-product, or wrong-variant acceptances; zero credential leaks; zero unverified distributor-image flow; correct conflict/fallback routing in every sampled failure; source-error rate ≤10%; p95 within the 60-second item budget. Canary one workspace/provider ≥7 days and ≥100 real items before broader enablement. Human Review remains mandatory for every item and is **not** an adequate substitute for these gates.
15. **Migrations.** Schema changes (item `source_type` + entry-policy version; nullable extraction `source_url`; extraction `source_type`/method/generation/accepted-attempt/hash provenance; `duration_ms` on attempts; `distributor_record` in the classification source CHECK) ship as versioned, backup-verified, transactional, PRAGMA-guarded, idempotent migrations. Fresh and upgraded databases converge. Existing rows are backfilled to policy `0`; historical route/projection rows remain readable and are never rewritten.
16. **Kill switch and rollback.** `BAYSTATE_CMS_SOURCING_ENABLED=false` + restart returns new imports to Discovery immediately and makes Sourcing retries use the audited fallback. Rollback never deletes evidence and never rewrites reviewed history; already-routed distributor items remain visible for operator quarantine after a correctness incident. In-flight items at kill time are reset to `sourcing/pending` (or Discovery) for operator action, never silently completed.
17. **Required acceptance coverage.** Tests must cover: flag parsing (absent/false spellings/malformed/invalid-mode/override); legacy-cohort isolation (policy-0 rows unclaimable); routing (qualified → extraction; insufficient → discovery; conflicts block); extraction materialization + evidence hash; cohort freezing with distributor provenance; promotion image gating; migration fresh/upgrade/idempotent/rollback; and kill-switch behavior.

**Consequences**:

- Amendment A is the ratified prerequisite for the `distributor_record_to_extraction` route and the default-on flip (satisfying the base ADR’s “separate structured-record fallback ADR” condition). Implementation follows `docs/plans/default-on-sourcing.md` (Milestones A–F) and the rollout runbook (`docs/runbooks/sourcing-engine-rollout.md`), which now includes the upgrade pin, backup verification, legacy-cohort exclusion, per-provider gates, rollback behavior, and incident quarantine.
- The capability is default-on only for **new** post-amendment imports; the legacy stranded cohort and all pre-amendment state are untouched and remain operator-controlled.
- No live provider call, live DB migration, catalog/ShopSite write, staging, or commit occurs during implementation; tests use temporary/in-memory databases.
- Remaining deferred: Phase 2 SFTP adapters (Orgill/PFX), PI-6 image rights integration, commerce price/inventory authority, and structured-record fallback beyond the v1 identity allowlist.

# Amendment B — Distributor Scraper Connectors and Merchandising-Depth Materialization

**Status**: ratified (product-owner grill session of 2026-08-15; implementation follows `docs/plans/distributor-scrapers-migration-plan.md`).

**Product-owner directive (paraphrased)**: *"Re-implement the distributor scrapers lost with the BayStateApp migration. Uploaded products must go through an initial scan through our distributors first. If we find the product on our distributors we skip discovery and extraction — the initial distributor scan provides enough data for curation."*

This amendment supersedes the following clauses of the base ADR and Amendment A:

- **Amendment A clause 8 (v1 identity-field allowlist)** → distributor-record materialization becomes **merchandising-depth**: identity fields plus description, features/bullets, category, dimensions, case pack, unit of measure, ingredients, and image URLs (display-only). **Price, inventory, and arbitrary provider fields remain excluded**; the source URL stays null (real product-page URLs live only on immutable `EvidenceAttempt.evidenceUrl`).
- **"Phase 2 SFTP adapters (Orgill/PFX)" deferral** → superseded as the primary transport for Orgill and Pet Food Experts by `html_scraper` connectors. The `ftp_catalog`/`csv` connector types remain available for future catalog-based distributors.
- **"Central Pet EDI 832 is excluded"** → Central Pet is now served by the centralpet.com `html_scraper` connector; the EDI 832 feed itself remains out of scope.

Amendment A clauses 1–7, 9–11, 13–17 and the base ADR's `bundle_to_curation` prohibition, evidence immutability/generation scoping, `secret_ref`-only credential handling, UPC/GTIN-first exact matching, hard-conflict manual resolution, review-mandatory, and image display-only rules remain in force. Amendment A clause 12 (images stay display-only until PI-6 verification) is **reaffirmed unchanged**.

**Normative amendments**:

1. **New closed connector type `html_scraper`.** The closed set becomes `api | ftp_catalog | csv | html_scraper | legacy_adapter`. Ships as a versioned, backup-verified, PRAGMA-guarded, idempotent migration (table CHECK constraint), plus shared Zod schema, client API types, and registry mapping. `legacy_adapter` remains reserved for historical connection rows and is never a production path. The registry keys on `(connectorType, distributorId)`.
2. **Five production connectors.** `orgill`, `pet_food_experts`, `phillips_storefront`, `bradley`, `central_pet` — TypeScript ports of the BayState Python adapters (`apps/scraper/scrapers/approved_sources/adapters/`), implementing the existing `DistributorConnector.lookupByGtin` contract. The existing Phillips (Endless Aisles REST) and BCI (OrderCloud REST) `api` connectors stay registered; two connector flavors per distributor may coexist and both are queried within a bounded generation. `providerId` disambiguates provenance (`phillips` vs `phillips_storefront`, `bci` vs `bradley`).
3. **Crawlee engine map.** Connectors are built on Crawlee. `PlaywrightCrawler` handles login and JS-rendered flows (orgill ASP.NET postback, phillips SFCC, PFX, central_pet); `CheerioCrawler` handles static extraction with authenticated session cookies (orgill, phillips_storefront, PFX, bradley; bradley keeps a browser fallback). No proxies in v1; proxy configuration may be added per-connector later without contract change.
4. **Authenticated sessions (memory-only).** Crawlee `SessionPool` holds cookies in worker memory only — `persistCookiesPerSession: false`, never persisted to disk, per the security mandate. Per-distributor `LoginAutomationConfig` constants (username/password/submit selectors, success/failure indicators) recovered from BayState. Credentials are structured JSON (`{"username","password"}`) in the existing `api_keys` secret value, resolved via `secret_ref`; a login failure triggers exactly one re-login, then a durable `source_error` with a stable auth code. All logging redacted.
5. **Selectors are code.** Recovered selectors (current Python adapters + the deleted legacy YAML archive, recoverable from BayState git history) become typed constants with ordered fallback chains inside each connector file. No runtime selector configuration surface; selector changes are reviewed code changes.
6. **Merchandising-depth materialization.** The deterministic materializer persists: identity fields (exact UPC/GTIN, distributor SKU, MPN, name, noncanonical brand, weight, whitelisted variant axes) **plus** description, features, category, dimensions, case pack, unit of measure, ingredients, and image URLs. Price, inventory, and arbitrary provider fields stay null/absent. Materialization remains fetch-free, profile-free, deterministic, generation-scoped, and provenance-attached; `extraction_method` bumps to a v2 marker.
7. **Conflict scope unchanged.** Hard conflicts remain identity-scoped (upc/gtin/MPN/weight/size/count/packCount/brand + connector-declared variant axes). Merchandising fields merge with per-field provenance and **never** trigger or block conflicts; the qualification authority and route table are unchanged.
8. **Bounded sessions.** Every connector honors the engine-composed deadline and caller `AbortSignal`; per-connector origin allowlists, response-size caps, `retryOnBlocked`, and rate limiting apply. No credential, cookie, or raw response crosses the connector boundary or is persisted; errors carry stable non-secret codes.
9. **Staged tiered rollout.** All five connections land **disabled**. Enablement order: tier 1 public storefronts (`bradley`, `central_pet`) → tier 2 auth-gated (`orgill`, `pet_food_experts`, `phillips_storefront`). Each tier passes the Amendment A rollout gates (fixtures, ≥100 labeled observations, zero false `found`, zero credential leaks, source-error rate and p95 budgets) through observe → manual → automatic per `docs/runbooks/sourcing-engine-rollout.md`.
10. **Testing.** Unit tests run offline on fixture HTML snapshots (captured from live sites, provenance-stamped) with the recovered test SKUs (orgill 755625321923, bradley 001135, central_pet 38777520, phillips 072705115310, PFX 33011808) and the old adapters' extracted-field expectations as ground truth. An env-gated live smoke script (port of `run_adapter_test.py`) verifies real sessions on demand; credentials never enter CI.

**Consequences**:

- **Item-number exact-match directive (2026-08-15)**: for `pet_food_experts` (and, by the same rule, any connector whose storefront exposes a catalog item number), an 8–14 digit lookup identifier that EXACTLY equals the PDP's distributor Item # (digits-only equality) and whose page also carries a real UPC/EA resolves to the product (`matchedIdentifier` stays the searched identifier; the page's real barcode travels as `distributorUpc`, newly carried by the identity schema and engine evidence). This is exact-equality only — never fuzzy/substring; a UPC-less page never matches; all other exact-match/wrong-variant semantics are unchanged.

- BayState is the migration source of record: the live Python adapters provide the field logic, the deleted `legacy-scraper-archive` YAML configs (git `5619f6a4^`) provide selector fallbacks and auth workflow references.
