# Research: ShopSite 15 Product Description vs More Information fields (db_xml.cgi / dbupload.cgi XML)

## Summary
ShopSite's official names are **Product Description** (UI/upload-field label) → XML element `ProductDescription`, and **More Information Text** ("More Info Page Text") → XML element `MoreInformationText`. Both element names are confirmed verbatim in ShopSite's official products DTD (`shopsiteproducts.dtd`), which also confirms `DisplayMoreInformationPage_` (trailing underscore) as the checkbox controlling whether a More Info page exists at all — populating `MoreInformationText` alone does not create or display a More Info page.

## Findings

1. **Exact official field names.** The Database Upload/Download Fields reference lists the two upload/download fields as:
   - **"Product Description"** — "Text describing the product." Field type: Text entry; default value: Null; possible values: "Any text string, including HTML tags, if desired. It is best to avoid the use of single and double quotation marks." [ShopSite help, Upload/Download Fields](https://help.shopsite.com/help/12.0/en-US/sc/pro/upload.fields.html)
   - **"More Information Text"** — "Descriptive text to appear on the More Information page for this product." Same type/default; "Any text string, including HTML tags, if desired." (Same page.) In the Edit Product Info back-office screen this appears in the "More Info Pages" section as the More Info page's descriptive text [Edit Product Info](https://help.shopsite.com/help/12.0/en-US/sc/pro/edit.product.info.html).

2. **Exact XML element names (authoritative DTD).** ShopSite publishes the products DTD that governs db_xml.cgi/dbupload.cgi XML at `http://www.shopsite.com/XML/1.9/shopsiteproducts.dtd`. Inside `<!ELEMENT Product (...)>`:
   - `<!ELEMENT ProductDescription (#PCDATA)>`
   - `<!ELEMENT MoreInformationText (#PCDATA)>`
   - Related elements: `DisplayMoreInformationPage_`, `MoreInformationGraphic`, `MoreInfoImageSize`, `MoreInfoTitle`, `MoreInfoMetaDescription`, `MoreInfoMetaKeywords`, `FileName`.
   Both target elements are optional (`?`) children of `Product`; both are `#PCDATA`. Source of record: the DTD itself, cited from [LexiConn's XML-upload walkthrough](https://www.lexiconn.com/blog/2010/03/how-to-quickly-get-your-products-into-shopsite-part-3-xml-upload/), which links it as "ShopSite's DTD". The same identifiers appear as custom-template tags `[-- PRODUCT.ProductDescription --]` and `[-- PRODUCT.MoreInformationText --]` in the [official template tag spec](https://help.shopsite.com/help/12.0/en-US/sc/pro/custom.template.spec-product.html), confirming they are the internal database field names used across XML, uploads, and templates.
   - **Naming gotcha:** checkbox-type elements get a trailing underscore in the XML/DTD (`DisplayMoreInformationPage_`, `DisplayName_`, `DisplaySKU_`, etc.), while plain text elements do not.

3. **Where each field is displayed.** Official docs describe the split explicitly:
   - Product Description renders on regular store/category pages next to the thumbnail image, styled by `DescriptionStyle`/`DescriptionSize` and the product template [Upload/Download Fields](https://help.shopsite.com/help/12.0/en-US/sc/pro/upload.fields.html), [Custom Template Tag Spec](https://help.shopsite.com/help/12.0/en-US/sc/pro/custom.template.spec-product.html).
   - More Information Text renders only on the dedicated per-product More Info page (`[-- DEFINE MORE_INFO_PAGE --]`). ShopSite's More Info FAQ explains the intended division: keep regular pages fast with "small product images ('thumbnails') and brief descriptions," and put "a larger picture and longer description on the More Info pages"; once defined, the product name/image on the regular page link to the More Info page, and customers can order directly from it ([More Info Page FAQs](https://help.shopsite.com/help/12.0/en-US/sc/pro/working/faq.prod.moreinfo.html)).

4. **Guidance about putting the product name into Product Description.** There is **no official ShopSite documentation recommending putting the product name into the Product Description field** for SEO or layout reasons. Documented guidance is the opposite direction: keep Product Description brief and push detail to the More Info page (FAQs above). What ShopSite does document for SEO is the separate **More Information Meta:Description** field ("The description text to be included in the HTML meta description tag"), which merchants tailor for search engines independently of the visible description [Upload/Download Fields](https://help.shopsite.com/help/12.0/en-US/sc/pro/upload.fields.html); ShopSite markets general SEO controls separately ([shopsite.com/seo.html](https://www.shopsite.com/seo.html)). Practically, since the template renders Name and Description as adjacent but distinct outputs (`[-- PRODUCT.Name --]` then `[-- PRODUCT.ProductDescription --]`), duplicating the name inside Product Description is a merchant/template choice, not a ShopSite-documented practice. For Bay State CMS curation: treat name-in-description as a project convention, not a ShopSite requirement.

5. **Requirements for MoreInformationText to actually appear.** Three things must line up:
   - The product must have a More Info **page defined**: the "Display more information page?" field ("Indicates whether a More Information page exists for this product", default unchecked) must be checked — XML element `DisplayMoreInformationPage_` [Upload/Download Fields](https://help.shopsite.com/help/12.0/en-US/sc/pro/upload.fields.html). Uploading `MoreInformationText` without enabling this leaves the text stored but unrendered/unlinked.
   - A file name is needed; if `FileName` is blank, ShopSite auto-assigns one (e.g., `page1.html`) on publish [Upload/Download Fields](https://help.shopsite.com/help/12.0/en-US/sc/pro/upload.fields.html).
   - The product's template must define a `MORE_INFO_PAGE` section (`[-- DEFINE MORE_INFO_PAGE --]`) and emit `[-- PRODUCT.MoreInformationText --]`; theme templates do this by default, and store-wide More Info colors/header/footer live under Preferences → More Info Pages ([Template tag spec](https://help.shopsite.com/help/12.0/en-US/sc/pro/custom.template.spec-product.html), [More Info FAQs](https://help.shopsite.com/help/12.0/en-US/sc/pro/working/faq.prod.moreinfo.html)). After import, a publish via `generate.cgi` is required to regenerate pages ([Automated XML Upload/Download](https://help.shopsite.com/help/14.0.1/en-CX/sc/pro/database.automated_XML_upload.html)).
   - Note: there is no per-product "template enabled" flag beyond the above; any product can have a More Info page regardless of which product template is assigned, as long as that template defines the MORE_INFO_PAGE block (all stock themes do).

6. **Gotchas: CDATA, size limits, 'none' defaults, empty elements.**
   - **CDATA / entities:** Text fields may contain HTML tags, so `<`, `>`, `&` must be entity-escaped (`&lt;` `&gt;`) or the whole value wrapped in `<![CDATA[ ... ]]>`. LexiConn (ShopSite hosting partner) documents both patterns with examples: `<Description><![CDATA[ 1 -> 2 -> 3 ]]></Description>` ([LexiConn XML guide](https://www.lexiconn.com/blog/2010/03/how-to-quickly-get-your-products-into-shopsite-part-3-xml-upload/)). CDATA is safe because both elements are `#PCDATA` in the DTD. Note CDATA cannot contain the literal sequence `]]>`; escape it as `]]]]><![CDATA[>` if needed (standard XML rule, not ShopSite-specific).
   - **Empty values:** empty elements serialize as self-closing tags (`<SaleAmount />`); mimic a real db_xml.cgi download for exact shape ([LexiConn](https://www.lexiconn.com/blog/2010/03/how-to-quickly-get-your-products-into-shopsite-part-3-xml-upload/)). Omitted fields are simply left unmodified: "ShopSite will not modify fields that are not included in the upload file" ([Upload/Download Fields](https://help.shopsite.com/help/12.0/en-US/sc/pro/upload.fields.html)).
   - **'none' defaults:** the literal `"none"` default applies to **image/graphic fields only** (Graphic, MoreInformationGraphic, option Image) — "If no graphic is specified, the field must contain none." It does NOT apply to ProductDescription or MoreInformationText, whose defaults are Null/empty ([Upload/Download Fields](https://help.shopsite.com/help/12.0/en-US/sc/pro/upload.fields.html)). Sending the string "none" as a description would render literally.
   - **Size limits:** no published character limit exists for either field in ShopSite docs; both accept "any text string, including HTML." Practical limits are HTTP POST/MIME size and server resources; the docs recommend batching very large databases (>10,000 records) into multiple files with `defer_linking=yes` ([Automated XML Upload/Download](https://help.shopsite.com/help/14.0.1/en-CX/pro/database.automated_XML_upload.html)). Treat absence of a documented limit as "unbounded but batch large payloads."
   - **Quotes:** for delimited-text uploads ShopSite advises avoiding single/double quotes in these text fields; in XML this is unnecessary (escaping/CDATA handles it) but harmless to follow.
   - **Fieldmaps:** XML element names in downloads can be overridden by a named fieldmap (`fieldmap=` option on db_xml.cgi); the DTD names above are the defaults. Verify against an actual export from the target store before relying on labels [Automated XML Upload/Download](https://help.shopsite.com/help/14.0.1/en-CX/pro/database.automated_XML_upload.html).

## Gaps
- The linked DTD is version 1.9 (the publicly hosted copy); ShopSite 15 may ship additional elements (e.g., newer Google/subscription fields), though `ProductDescription` and `MoreInformationText` have been stable across every version observed (7.x–14.x docs). Recommended verification: run a real `db_xml.cgi` export from the target ShopSite 15 store and diff element names (this is also ShopSite's own recommended practice).
- No official statement found endorsing product-name-in-description for SEO; if the project wants a citation-grade rationale it will remain an internal convention.
- Exact maximum payload sizes for MIME-encoded uploads are undocumented; only batching guidance exists.
